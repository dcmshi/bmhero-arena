## Open items, highest value first

### 1. ~~The arena doesn't FRAME~~ — RESOLVED 2026-07-27

**A1.5 is done.** `ARENA_CAM_DIST` 2800 frames the whole 1900x1900 arena, centred,
with margin on every side. The camera code never needed fixing.

`tools/capture-game.ps1` was capturing **only the top-left quarter of the frame**
— the backbuffer is 1600x900, but `GetClientRect` reports 800x450 to a
non-DPI-aware process, so PrintWindow blitted a quarter of the surface unscaled.
A centred arena drifts out of that crop as the camera pulls back, which is exactly
the "floor hugs the corner and shrinks" symptom. Fixed with `SetProcessDPIAware()`
(§8.17).

It cost three wrong root causes — `gView.at` overwrite, far clip plane, chunk
culling — all real mechanisms, correctly RE'd, all irrelevant. A RenderDoc capture
of the same session settled it in one shot: clip-space depth `w ∈ [2006.6, 2966.6]`
against a predicted `[2011.6, 2961.6]` for the measured floor.

**New:** `tools/rd-capture.ps1` (+ `rd_trigger.py` / `rd_saveframe.py` /
`rd_analyse.py`) captures a frame with no keyboard involved, via qrenderdoc's
embedded Python over target control. Use it whenever a screenshot disagrees with a
measurement.

### 2. ~~A1.5 anim regression~~ — RESOLVED 2026-07-27 (it was never the camera)

The A/B that blamed the camera ran across **two builds**. With the new
`ARENA_CAM_OFF=1` runtime toggle the A/B runs on **one binary**, and the gate
fails **identically** with the camera on and off.

Real cause: `func_80024744` (the walker) runs before our anim block and
re-asserts its own animation **every frame**, so a one-shot trigger survives
exactly one frame — regardless of camera, and regardless of standing still
(which **corrects §8.5c**). Fixed by holding: a 24-frame window re-asserts the
pose whenever the walker takes it.

The gate was also asserting the impossible — `-Rising` demanded an advancing
frame counter, but holding requires re-triggering, which restarts the anim.
`-AnimProbe` now asserts `[animw] +12 idx=29`, which is its actual intent.

Gate green both ways; 5/5 soak. §8.18.

**Still open:** the pose is *static* (held, not animated). Real animation needs
the game's own set action state engaged so the walker plays it itself.

## Traps that cost real time

1. **A failed build leaves the previous exe, and the soak tests it happily.**
   `build.ps1` retries once, but always confirm `BUILD OK` before trusting a probe.
2. **Validate a measuring tool against ground truth before trusting it.**
   `capture-game.ps1` cropped the frame to a quarter for weeks and cost three
   wrong root causes; its output looked entirely plausible. When a model and an
   instrument disagree repeatedly, suspect the instrument. `tools/rd-capture.ps1`
   is the independent source. §8.17.
3. **A gate can pass for the wrong reason.** `-Constant` on the rail camera's yaw
   passed because it happened to sit still; `-Absent` passes vacuously if the run
   never got in-arena. Assert on a value only *you* set, and pair `-Absent` with
   something positive.
4. **Measure the geometry, not the player.** Any measurement taken by moving the
   player is confounded by the very bounds you are checking. §8.15.
5. **Log which map you measured.** The render routine runs in every level, so
   `[capture]` fires wherever the draw gate opens — including the stage-select map.
6. **MSYS2 gcc fails silently** (exit 1, no diagnostic) when invoked by absolute
   path without its own `bin` on PATH. All the PS scripts prepend it.
7. **Export name collisions.** An export in `syms.ld` becomes a C symbol with the
   `(rdram, ctx)` signature — it must not share a name with the native
   implementation. Follow the `arena_export_*` shim convention.
8. **Mode gates are duplicated in `main.cpp`** — a new `ARENA_AUTO_BATTLE` mode
   must be added to BOTH the frontend-mash list and the launcher list, or the boot
   hangs before reaching the arena.

## Commands worth knowing

```powershell
# canonical
tools\gate.ps1                                   # everything CI runs, one command
tools\tune-report.ps1 -Compare base,turn=1456    # feel metrics sweep
tools\repin.ps1                                  # after an intentional sim change
tools\trace-diff.ps1 -A base -B friction=0.020   # first diverging tick

# fork
.\build.ps1 -Config rwdi -Soak 5                 # build + soak, fails unless green
.\tools\decomp-func.ps1 func_8001994C            # typed C for any function
.\tools\arena-log.ps1                            # summarise arena_bridge.log
.\tools\arena-soak.ps1 -Mode 6 -Absent 'GUARD FIRED'      # must-never-happen gate
.\tools\arena-soak.ps1 -N 1 -Mode 7 -Expect '\[raster\] DONE'   # measure the floor

# floor raster at finer resolution, and camera framing — both no-rebuild
```
