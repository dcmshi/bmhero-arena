## Open items, highest value first

### 1. Re-match sim geometry to the real floor  ← the keystone

The real floor is **smaller** than the sim's collidable bounds, so the sim walks
the player off the edge (§8.5a violation). This is the root cause of the falling
*and* of the camera framing being off — fixing it makes the floor guard
redundant and gives the camera its true centre.

**Blocked on:** a complete floor map. The `[floor]` tracker works but the sweep
stalls — the guard parks the player at the edge instead of letting it continue,
so X is still only `[0..353]`.

**Suggested approach:** a measurement mode that, on hitting the sentinel, records
the edge and **nudges the player back inward** rather than parking it, so one run
walks the whole boundary. Then set `arena_geom.h` from the measured extent
(sim change → `TUNE_VERSION` 8 + `tools/repin.ps1`).

### 2. A1.5 anim regression — isolated, unexplained

The A1.5 camera **breaks the A1.4 set-pose gate**. Clean A/B, same build
otherwise:

| build | anim gate |
|---|---|
| camera stamps **disabled** | `idx=29 frames=[0,0,2]` → **PASS** (2/2) |
| camera stamps **enabled** | `idx=29 frames=[0,0]` → **FAIL** (3/3) |

**The gate is deliberately left RED.** It is reporting something true; weakening
it would hide a real regression. Mechanism unproven — the likely path is that
yaw 0 changes the stick's world direction (the game rotates the stick by
`rot.y`), changing whether the player is wall-pinned when Z lands, so the walker
re-asserts locomotion over the pose sooner.

**Suggested first step:** log the stick vector *after* `func_80024744`'s rotation
with the camera on vs off, and compare.

### 3. Camera framing

`ARENA_CAM_DIST` is **2200** — frames most of the floor, not all. Pushing to 4000
moved the arena *off-centre*, which is symptom of item 1 (`at` is anchored on the
player's spawn, which is offset from the true floor centre). **Finish item 1
first**; framing then falls out of the measured centre.

## Traps that cost real time this session

1. **A failed build leaves the previous exe in place, and the soak tests it
   happily.** This silently invalidated an A/B run. `build.ps1` retries now, but
   always confirm `BUILD OK` before trusting a probe result.
2. **A constancy gate can pass for the wrong reason.** `-Constant` on the rail
   camera's yaw passed because it happened to sit still. Assert on a value only
   *you* set.
3. **MSYS2 gcc fails silently** (exit 1, no diagnostic) when invoked by absolute
   path without its own `bin` on PATH. All the PS scripts prepend it.
4. **Export name collisions.** An export in `syms.ld` becomes a C symbol with the
   `(rdram, ctx)` signature — it must not share a name with the native
   implementation. Follow the `arena_export_*` shim convention.
5. **Mode gates are duplicated in `main.cpp`** — a new `ARENA_AUTO_BATTLE` mode
   must be added to BOTH the frontend-mash list and the launcher list, or the
   boot hangs before reaching the arena.
