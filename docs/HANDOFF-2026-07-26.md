## Open items, highest value first

### 1. `gView.at` is not honoured at draw time

The `ARENA_CAM_DIST` sweep **proved our gView write drives the picture** (zoom
tracks it exactly), and the log confirms `wrote_at=(0,340,0)` — the measured floor
centre. But **the rendered view is centred on the player**, and the player's
screen position drifts systematically as distance changes. So pitch/yaw/dist are
honoured and `at` is not, somewhere between our stamp and the draw.

A1.5 therefore works as a fixed-**orientation follow** camera. That still delivers
its real goal — stable yaw, so a held stick direction stops curving — but not the
static whole-arena framing.

**Suggested first step:** sample `gView` inside the *draw* routine
(`func_800821E0`) rather than the update routine, to distinguish "overwritten in
between" from "the projection doesn't use `at`".

`ARENA_CAM_DIST` is 1800 (best of 1200/1800/2800/4000 by screenshot) and is
env-overridable, so re-sweeping is cheap.

### 2. A1.5 anim regression — still RED, still unexplained

## Traps that cost real time

1. **A failed build leaves the previous exe, and the soak tests it happily.**
   `build.ps1` retries once, but always confirm `BUILD OK` before trusting a probe.
2. **A gate can pass for the wrong reason.** `-Constant` on the rail camera's yaw
   passed because it happened to sit still; `-Absent` passes vacuously if the run
   never got in-arena. Assert on a value only *you* set, and pair `-Absent` with
   something positive.
3. **Measure the geometry, not the player.** Any measurement taken by moving the
   player is confounded by the very bounds you are checking. §8.15.
4. **Log which map you measured.** The render routine runs in every level, so
   `[capture]` fires wherever the draw gate opens — including the stage-select map.
5. **MSYS2 gcc fails silently** (exit 1, no diagnostic) when invoked by absolute
   path without its own `bin` on PATH. All the PS scripts prepend it.
6. **Export name collisions.** An export in `syms.ld` becomes a C symbol with the
   `(rdram, ctx)` signature — it must not share a name with the native
   implementation. Follow the `arena_export_*` shim convention.
7. **Mode gates are duplicated in `main.cpp`** — a new `ARENA_AUTO_BATTLE` mode
   must be added to BOTH the frontend-mash list and the launcher list, or the boot
   hangs before reaching the arena.

## Commands worth knowing

```powershell
# canonical
tools\gate.ps1                                   # everything CI runs, one command
tools\tune-report.ps1 -Compare base,turn=1456    # feel metrics sweep
tools\repin.ps1                                  # after an intentional sim change
tools\trace-diff.ps1 -A base -B friction=0.020   # first diverging tick

# fork
.\build.ps1 -Config rwdi -Soak 5                 # build + soak, fails unless green
.\tools\decomp-func.ps1 func_8001994C            # typed C for any function
.\tools\arena-log.ps1                            # summarise arena_bridge.log
.\tools\arena-soak.ps1 -Mode 6 -Absent 'GUARD FIRED'      # must-never-happen gate
.\tools\arena-soak.ps1 -N 1 -Mode 7 -Expect '\[raster\] DONE'   # measure the floor

# floor raster at finer resolution, and camera framing — both no-rebuild
$env:ARENA_RASTER_N='201'; $env:ARENA_RASTER_STEP='10'
$env:ARENA_CAM_DIST='2400'
```
