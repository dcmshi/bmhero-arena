# Oracle 2.0: verb-table choreography + anim-timeline diff — design

**Date:** 2026-08-01
**Status:** approved in-conversation (feel round 11 wrap-up); this document is
the reviewable record.
**Scope:** fork-side only (`dcmshi/BMHeroRecomp`). No sim changes; the pinned
hash `04e8af49` (v18) must not move.

## Problem

Every feel-round bug since round 9 was the same species: an animation state
combination nobody had measured (carry+move, charge+move, release on the
window-close frame, midair release). The oracle only measures verbs that were
hand-picked in advance, so each new combination costs a human boot to notice
and a probe round to pin down. Two structural fixes, approved as "1 and 2":

1. **Anim-timeline goldens + auto-diff** — record vanilla's *entire* animation
   timeline per verb, reproduce the choreography in the arena, and diff the
   two automatically. Any wrong clip, wrong duration, or missing transition in
   a covered verb becomes a gate line instead of a feel report.
2. **One shared verb table** — choreography written once, in TICK units, and
   consumed by both the vanilla oracle script and the battle probe. Kills the
   polls-vs-ticks 2:1 conversion bug class (paid for three times) and makes a
   new verb a table row instead of two hand-rolled poll windows.

## Non-goals

- Y/XZ trace goldens (proposal 3) — later slice; the channels already exist.
- Replacing the 16 bespoke oracle-gate checks. They encode *semantics* (rest
  lift, impact detonation, plateau legality) that a timeline diff cannot; they
  stay as-is.
- Any change to sim code, tuning, or the recomp patches' render behaviour.

## Part A — verb tables

New fork header `src/main/verb_script.h`, included only by `main.cpp` (native
side; the MIPS patches never see it):

```c
typedef struct {
    const char* name;    /* phase marker at row start; NULL = unnamed row   */
    uint32_t    start;   /* TICKS from the script origin                    */
    uint32_t    dur;     /* TICKS the row stays active                      */
    uint16_t    buttons; /* N64 button mask OR'd in while active            */
    int8_t      stick_y; /* -1 / 0 / +1 (full deflection; matches current)  */
} VerbRow;
```

Two tables, one driver:

- `kOracleScript[]` — the vanilla single-player script. Origin = the first
  post-mash poll (`op == 1` today). Every row is today's hand-rolled window
  divided by 2 (all current windows are even-poll; verified before writing).
- `kBattleScript[]` — the mode-13 arena probe. Origin = the first probe poll.
- `verb_apply(rows, n_rows, tick, *buttons, *stick_y, mark_cb)` — the ONLY
  place ticks convert to polls (poll = tick × 2). Called from both branches of
  `soak_get_n64_input`. `mark_cb` fires once at each named row's start:
  vanilla rows call `arena_oracle_phase(name)` (log format unchanged); battle
  rows call a new native bridge entry `arena_verb_mark(name)` which logs
  `[verb] <name> t<sim-tick>`.

**Hard regression requirement:** after the refactor, a vanilla oracle boot
must reproduce `tools/oracle/goldens.json` **byte-identical**. That is the
proof the tables encode exactly today's choreography. A mode-13 boot must
keep all 16 oracle-gate checks green for the same reason.

## Part B — anim timelines

**Representation.** A verb's timeline is its animation stream run-length
encoded: an ordered list of `[clip_index, frames]` runs. Runs shorter than 2
frames are dropped on both sides (transition jitter; the anim engine steps
the frame counter +2/frame and single-frame blips carry no meaning).

**Vanilla capture.** `tools/oracle.ps1` gains an RLE pass over the existing
per-frame `[oracle-anim]` channel: for each phase marker, the window from its
`n` to the next marker's `n` becomes that verb's run list. Output:
`tools/oracle/timelines.json`:

```json
{ "carrywalk": { "frames": 60, "runs": [[17, 58]] },
  "holdlong":  { "frames": 180, "runs": [[14, 60], [26, 118]] } }
```

Committed next to `goldens.json`, regenerated by the same `-Force` flow, with
the same "diff shown, refuse silent overwrite" behaviour.

**Arena capture.** The bridge logs `[animrun] idx=<i> len=<n> t<tick>` on
every walker anim index change in battle (from the per-frame latch that
already exists in `arena_dbg_anim`; `len` = frames the previous index held —
no cap, unlike the 28-line `[anim]` burst). Together with the `[verb]`
markers this reconstructs the arena's per-verb run lists.

**Differ.** `tools/anim-diff.ps1 -ArenaLog <file> [-Timelines <file>]
[-Verbs a,b,c]`:

- Verbs compared = the intersection of verb names present in
  `timelines.json` and `[verb]` markers in the arena log (optionally
  restricted by `-Verbs`). Verbs that intentionally differ between the two
  worlds (different fuse lengths, arena-only rules) simply never share a
  name.
- Per verb: compare run lists in order. A run matches when the clip index is
  equal and the length is within ±3 frames (the bespoke checks' tolerance).
  The comparison window is `min(vanilla frames, arena frames)`; the final run
  is truncated to it. An extra, missing, or re-ordered run is a divergence.
- Output: one line per verb — `PASS` or `FAIL run <k>: vanilla (idx,len) vs
  arena (idx,len)` — and exit code = number of failing verbs.

**Initial shared verb set** (both tables carry these names): `carrywalk`,
`holdlong` (carry idle → windup transition timing), `carryjump`, `relairB`
(the midair toss), `setR` (the ground set pose). More verbs join by giving
rows the same name on both sides — no differ changes needed.

**Gate.** `tools/oracle-gate.ps1` check 17: run `anim-diff.ps1` against the
mode-13 log already produced for checks 11–16; red if any verb fails.

**Falsifiability** (project rule: a gate that asserts its own assumption
cannot fail): during implementation, run once with
`ARENA_CARRY_WALK_ANIM=26` and confirm check 17 goes red on `carrywalk`
before it is allowed to count as green evidence.

## Error handling

- A verb present in `timelines.json` but missing from the arena log (probe
  died early, marker never fired) = FAIL for that verb, not a silent skip —
  the round-10 "vacuous reproduction" lesson (a green over an empty scene).
- `oracle.ps1` refuses to write a timeline whose verb has zero anim samples.
- The differ prints the verbs it compared; comparing zero verbs is exit 1.

## Verification plan

1. Refactor to tables → vanilla boot → **goldens byte-identical**; mode-13
   boot → 16/16 bespoke checks green. (Choreography equivalence proven.)
2. Generate `timelines.json`; a second independent vanilla boot must
   reproduce every verb within the differ's own tolerance (instrument
   validated the same way goldens were: byte-stability across boots).
3. Check 17 green on the real build; falsifiability run red as specified.
4. Full `build.ps1 -Config rwdi -Soak 5` green on the final exe.

**Build discipline for this slice:** the human feel-boots between rounds —
NEVER kill a running `BMHeroRecompiled` process to free the exe lock; wait
for it to exit.
