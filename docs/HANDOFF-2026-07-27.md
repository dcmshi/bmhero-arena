## What happened this session

Three feel tests drove almost all of it. The pattern worth carrying forward: the
user reports a symptom, the first instinct is usually wrong, and measuring
against the game's own value settles it in one run.

**A1.5 camera — the camera was never broken.** `tools/capture-game.ps1` was
capturing only the top-left quarter of the frame (1600×900 backbuffer, but
`GetClientRect` reports 800×450 to a non-DPI-aware process). A centred arena
drifts out of that crop as the camera pulls back — exactly the "floor hugs the
corner and shrinks" symptom. One line (`SetProcessDPIAware()`). It cost three
wrong root causes, all real mechanisms, all irrelevant. RenderDoc settled it in
one capture. Framing is done at `ARENA_CAM_DIST` 2800. §8.17.

**A1.4 anim gate — the attribution was wrong.** The A/B that blamed the camera
ran across two builds; on one binary with `ARENA_CAM_OFF` the gate fails
identically either way. Real cause: the walker re-asserts its own animation every
frame, so a one-shot trigger survives exactly one frame. Fixed by holding. §8.18.

**A1.2g finished** — hazards suppressed via `gDebugInvincibileFlag` (one flag
gates the whole damage class; verified the tile is still *detected* with its
damage gone), exit trigger not reproducible (it was the anchor bug driving the
player off the map), and the HUD done by **reusing Hero's own** rather than an
RmlUi overlay. §8.20, §8.21.

**Feel-test fixes, v8 → v14.** Each was a real bug; three of them were things I
had first explained away:

| report | actual cause | version |
|---|---|---|
| W/S inverted | recomp maps W to `Y_AXIS_POS`; sim wants forward negative. Negated in the adapter, not the sim | 9 |
| "stuck in place" | `PHASE_ROUND_END` was terminal and `gameplay` gates input off there. **A frozen sim is still deterministic**, which is why the determinism suite could never catch it | 9 |
| turn drift on a stop-and-reverse | I called it "by design"; the user pushed back; probe mode 9 measured the game's own `moveAngle` snapping 180→0 in ONE frame | 9, then 12 |
| spawn on a damage tile | surface-type raster found type `0xF7` at 100 cells; spawns moved 6.5 → 5.5 | 10 |
| knockback "reverses run direction" | the speed model re-projects the *current* velocity's magnitude along facing, laundering the blast impulse into run speed | 12, 13 |
| dead player still throwing; double bombs | the game's own player was still reading the controller alongside the sim | fork-side |

**Action poses — set 41 (was 29), kick 32.** The set pose had been derived from
the state machine and gated by an assertion that could not fail (*"index 29 is
playing"* is true no matter what 29 draws), so it stayed green through three feel
tests reporting a throw. Settled by rendering the whole asset table. §8.22.

## Open items, highest value first

### 1. Feel-boot the action poses and everything since v11

Set/kick poses, respawn, the skid fix, and the HUD are all soak-verified and
**none of it is feel-verified**. The poses in particular are a judgement call:
`ARENA_SET_ANIM` / `ARENA_KICK_ANIM` swap to 42 / 33 at runtime if the other
member of each pair reads better in motion.

### 2. The poses are STATIC

Both hold the correct pose but the frame counter stays pinned at 0 — holding
means re-triggering, and re-triggering restarts the clip
(`tools\arena-log.ps1` reports `STATIC (set but never advanced)`). Real animation
needs the game's own action state engaged so the walker plays the clip itself.
The pose is now the *right* pose; it just doesn't move. §8.18, §8.22.

### 3. Explosion visual

Detonation is still "the bomb vanishes". Documented approach: reuse a bomb's own
actor as its blast, which stays under the ~8-actor model-pool ceiling that forced
dropping the separate blast actors in A1.2c. §8.13.

### 4. Respawn is a TESTING ACCOMMODATION

`TUNE_RESPAWN_TICKS` exists so a feel tester isn't stuck watching after a death.
The shipping mode is stock-based elimination. Revisit before calling the ruleset
done — see the v14 commit message.

### 5. Real bomber mesh for puppets 1–3

Players 1–3 are still red bomb-mesh placeholders. The documented lead: player 0

tracing `gPlayerObject`'s anim-instance bind. §8.5b.

### 6. Real battle arena, then A3

## Traps that cost real time

1. **A gate can assert your own assumption and never fail.** The anim gate
   checked that index 29 was *playing*, not what 29 *drew*. When a gate is green
   and the user reports the symptom it was written for, suspect the gate. Pair it
   with something you did not choose.
2. **A call-graph search answers "is this used?", never "does this exist?".**
   Kick animations were declared non-existent because no code path played them;
   they were sitting unreferenced in the asset table. For an asset, enumerate and
   render it.
3. **A failed build leaves the previous exe and the soak tests it happily.**
   Always confirm `BUILD OK` before trusting a probe result.
4. **Validate an instrument before trusting it.** `capture-game.ps1` cropped to a
   quarter frame for weeks and its output looked entirely plausible. §8.17.
5. **Measure the geometry, not the player.** Any measurement taken by moving the
   player is confounded by the bounds you are checking. §8.15.
6. **Probe timing is not tick timing.** The input poll counter runs ~45 ahead of
   the sim tick, so a button at poll 215 lands at tick ~175 — inside the 180-tick
   countdown, silently dropped. §8.22.
7. **Literal `\n` in C string content** broke the build once and CI once. Use the
   Edit tool for C strings, not shell heredocs.
8. **MSYS2 gcc fails silently** (exit 1, no diagnostic) when invoked by absolute
   path without its own `bin` on PATH. The PS scripts prepend it.
9. **Export name collisions.** A `syms.ld` export becomes a C symbol with the
   `(rdram, ctx)` signature — it must not share a name with the native
   implementation. Follow the `arena_export_*` shim convention.
10. **New `ARENA_AUTO_BATTLE` modes are gated in TWO places in `main.cpp`** — the
    frontend-mash list and the launcher list — or the boot hangs before the arena.

## Commands worth knowing

```powershell
# canonical
tools\gate.ps1                                   # everything CI runs, one command
tools\tune-report.ps1 -Compare base,turn=1456    # feel metrics sweep
tools\repin.ps1                                  # after an intentional sim change
tools\trace-diff.ps1 -A base -B friction=0.020   # first diverging tick

# fork
.\build.ps1 -Config rwdi -Soak 5                 # build + soak, fails unless green
.\tools\arena-log.ps1                            # summarise arena_bridge.log
.\tools\decomp-func.ps1 func_8001994C            # typed C for any function
.\tools\anim-contactsheet.ps1                    # 106 labelled pose PNGs -> tools\anims\
.\tools\rd-capture.ps1                           # RenderDoc frame, no keyboard

# gates
.\tools\arena-soak.ps1 -AnimProbe                             # set pose  (idx 41)
.\tools\arena-soak.ps1 -Mode 10 -Expect '\[kick\] pose idx=32'  # kick pose
.\tools\arena-soak.ps1 -Mode 6 -Absent 'GUARD FIRED'          # must-never-happen
.\tools\arena-soak.ps1 -N 1 -Mode 7 -Expect '\[raster\] DONE'   # measure the floor

# runtime knobs, no rebuild
$env:ARENA_SET_ANIM='42'; $env:ARENA_KICK_ANIM='33'   # try the other pose
$env:ARENA_CAM_DIST='2400'; $env:ARENA_CAM_PITCH='30' # framing / angle
$env:ARENA_CAM_OFF='1'                                # A/B the camera on ONE binary
$env:ARENA_RASTER_N='201'; $env:ARENA_RASTER_STEP='10'
```
