## Traps that cost real time

The 08-04 list still applies in full and is **not** repeated here — read it
there (transcribed engine constants decay; fail-open fallbacks make failures
look like passes; PS7/PS5 `ConvertTo-Json` indent differently; the first
`-Patches always` link can lose a regen race and the retry is authoritative;
`gObjInfo` is frontend-roster data and is empty in warped levels). Older ones
are in 08-02.

New this session:

- **A write that demonstrably lands can still be invisible — verify the
  CONSUMER, not the write.** The tint spike's per-object light-colour words
  provably reached the RSP: the arena floor's grid lines changed to the last
  puppet's colour. The bombers moved by ≤2/255, because the character material
  does not have SHADE in its colour equation at all. Two boots went into
  strengthening a write that was never the problem. The generalisation of "a
  gate that asserts your own assumption cannot fail": pair a write with
  evidence from something you did not choose — here, an object that visibly DID
  change was the diagnosis.
- **A canned probe input's SIGN is part of the instrument.** The plan's bot
  drove `sy = +32` for "full forward"; the sim's forward is negative sy, so
  player 1 ran at the wall 2 units behind its spawn and RUN lasted 19 ticks
  instead of 240 — a window short enough that a careless probe would still have
  passed. Same family as "measure the geometry, not the player": validate the
  driver before trusting what it measures.
- **Measure the clock before designing around it.** The plan carried a whole
  conditional task for manually pumping puppet anim frames. One bounded 10-frame
  `[pframe]` burst showed `+2/frame` — the engine's own rate — and the task was
  deleted unwritten. The measurement cost one boot; the task would have cost a
  session and added per-frame writes to a draw path.
- **A negative spike has nothing to commit.** With the code reverted, the
  deliverable is the §8.41 paragraph, not a diff. Don't read the absent code
  commit as a skipped step — and don't keep a knob that does nothing useful
  just to have something to show.
- **A knob listed in `play.ps1`'s clear-list but given no switch is
  UNSETTABLE through `play.ps1`.** `ARENA_PUPPET_MESH` sat in that state, so
  08-04's own "`ARENA_PUPPET_MESH=0` A/Bs the bombers" instruction silently did
  nothing — the human would have exported it, seen bombers anyway, and concluded
  the mesh knob was broken. Caught only by reading `play.ps1` before shipping a
  checklist that depended on it (validate the instrument, §"validate instruments
  first" — including the launcher). Adding a knob to the clear-list without a
  matching switch is now the thing to check.
