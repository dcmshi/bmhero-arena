## Traps that cost real time (new since 08-02 — older ones in that file)

- **A transcribed engine constant is a decay bomb.** cfg `0x13` was correct
  in the MENU file-1 context and one-past-the-end in-level (19 sections,
  0..18) — `func_80010408` returns NULL below count and the bind AVs on it.
  The fix that can't go stale: the engine's files are SELF-DESCRIBING
  (header +4 = section count, +0xC = inline 12-byte entries, type 1 =
  skeletal) and `func_8001BD44` records each model's source on its pool
  slot — walk the player's own source at runtime (§8.40).
- **Fail-open fallbacks make failures look like passes.** Boot 2 of the
  bomber hunt fell back to bomb placeholders silently and the gate stayed
  green; the diagnosis was the ABSENCE of a debug tag. Log the failure
  path unconditionally, not just the success path.
- **PS7 and PS5 `ConvertTo-Json` INDENT differently**: regenerating
  `timelines.json` under PS7 produces a ~380-line formatting-only diff
  (same keys/order/values). Keep the committed formatting; take only value
  deltas (`git checkout -- timelines.json` after `-FromLog` runs).
- **The first `build.ps1 -Patches always` link can fail on a regen race**
  (undefined `fbits_*`/`arena_cam_stamp_*`); the script retries once and
  the retry is authoritative. Don't debug the first failure.
- **`gObjInfo` is frontend-roster data.** In warped arena levels it is
  empty INCLUDING the player's own entry, from the very first routine
  call. Anything needed from it must come from live object state instead
  (model slots record their source; anims come via `D_80115808`).
